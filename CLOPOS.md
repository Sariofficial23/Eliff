# 🧾 Clopos (касса) — заказы из бота в POS

Заказ из Telegram-бота сохраняется в базе, уходит в группу курьеров (как и раньше)
и **дополнительно** отправляется в кассу Clopos. В кассе он появляется с ручным
подтверждением (`auto_order_accept: false`): кассир принимает его в разделе
онлайн-заказов Clopos.

Пока переменные Clopos не заполнены, интеграция **выключена** и бот работает как
раньше.

Используется **Open API v2** (`https://integrations.clopos.com/open-api/v2`),
авторизация `POST /auth` с `client_id / client_secret / brand / integrator_id`,
дальше заголовок `x-token`. Схему v1 (`open-api.clopos.com`, OAuth) не смешиваем.

---

## 1. Ключи — только в Render

Render → `elif-backend` → **Environment** → **Add Environment Variable**:

| Переменная | Откуда |
|---|---|
| `CLOPOS_CLIENT_ID` | Clopos → Add-ons → Open API |
| `CLOPOS_CLIENT_SECRET` | там же (секрет, никому не пересылать) |
| `CLOPOS_BRAND` | бренд заведения в Clopos |
| `CLOPOS_INTEGRATOR_ID` | там же |
| `CLOPOS_VENUE_ID` | номер филиала (число) |

Необязательные:
- `CLOPOS_SALE_TYPE_DELIVERY` — ID типа продажи «Доставка». Если не задан, берётся
  тип с `system_type = DELIVERY` (видно в админке).
- `CLOPOS_COLA_PRODUCT_ID` — ID Coca-Cola в Clopos (для предложения колы в корзине).
  Без него заказ с колой не уйдёт в кассу и будет помечен ошибкой.
- `CLOPOS_DELIVERY_PRODUCT_ID` — если доставку в кассе учитывают отдельным товаром.
  Без него стоимость доставки передаётся в `delivery_fee`. Двойного начисления нет.

**Save Changes** → Render перезапустится. В логах: `🧾 Clopos navbati ishga tushdi`.

Ключи не храним в GitHub и не пишем в переписку.

## 2. Проверка и сопоставление товаров (админка → Настройки → «Касса Clopos»)

1. **Проверить подключение**: должно быть «Авторизация: успешно» и список типов продаж.
2. **Связать товары по названию**: проставляет Clopos ID товарам с точно таким же
   названием (вручную заданные ID не трогает). Показывает товары, которые не нашлись,
   и различия в цене.
3. Остальным товарам укажите ID вручную: **Mahsulotlar → Tahrir → Clopos ID**. Номера
   видны в кнопке **«Каталог Clopos»**.
4. **Пробный заказ** отправляет один товар от тестового клиента «TEST Elif bot»
   (без реального телефона). Его можно отклонить в кассе.

Если в заказе есть товар без Clopos ID, такой заказ **не отправляется частично**: он
получает статус «Xato» с названием товара. После того как ID назначен, нажмите
**«Qayta yuborish»**.

## 3. Что уходит в кассу

- клиент: ищется по телефону (`GET /customers`, фильтр `phones`, точное совпадение
  цифр), а если не найден, создаётся (`POST /customers`). Передаётся реальный
  `customer.id` из Clopos и `customer_discount_type: 0`;
- товары, количество и цены **из базы бота**, а не из запроса мини-приложения;
- доставка пересчитывается по настройкам (порог бесплатной доставки и цена);
- тип продажи «Доставка», филиал, `order_number = ELIF-<номер заказа>`;
- комментарий начинается с `Telefon: … | Manzil: …`; телефон и адрес не обрезаются;
- если сумма мини-приложения расходится с серверной, в комментарий добавляется
  `Diqqat: …`.

Скидок в боте сейчас нет: `oldPrice` используется только для показа зачёркнутой цены.

## 4. Статусы в админке (Buyurtmalar → колонка «Kassa»)

| Статус | Что значит | Что делать |
|---|---|---|
| Navbatda / Yuborilmoqda | в очереди / отправляется | ждать |
| Kassada + ID | заказ в Clopos | кассир принимает в Clopos |
| Xato | неверные данные (нет ID товара, 400/422, неверные ключи) или 6 неудачных попыток | исправить → «Qayta yuborish» |
| Noma'lum | запрос ушёл, но ответа не было (тайм-аут, 500, перезапуск) | найти `ELIF-<номер>` в Clopos: если заказ там есть → «Kassada bor», если нет → «Qayta yuborish» |

Защита от дублей:
- очередь хранится в базе вместе с заказом и после перезапуска продолжается;
- временные ошибки (нет связи, 429/502/503) повторяются автоматически: 1, 2, 5, 10,
  30 минут;
- после тайм-аута система сначала ищет `ELIF-<номер>` в кассе и сама **никогда не
  отправляет заказ повторно**. Повтор возможен только после подтверждения
  администратора.
